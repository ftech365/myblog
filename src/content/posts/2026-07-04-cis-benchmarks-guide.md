## はじめに

「サーバーのセキュリティを強化したい」「現状の設定に問題がないか監査したい」といった要望は、システム運用の現場でよく挙がる。こうした要望に対応する際、自己流の判断ではなく、業界標準の基準に沿って設定されているかどうかを確認していく進め方が求められる。その代表的な拠り所となるのが **CIS Benchmarks** である。

本記事では、CIS Benchmarksの構成の読み方から実務での入手方法までを整理する。あわせて混同されやすい **CVSS・CVE・CWE** との違いにも触れ、脆弱性対策の全体像の中でCIS Benchmarksがどこに位置するのかを補足する。

## 概要

**CIS Benchmarks** は、**CIS（Center for Internet Security）** という非営利団体が公開している、OS・ミドルウェア・クラウドサービスなどの**セキュリティ推奨設定集**である。Windows、Linux、各種ブラウザ、AWSやAzureといったクラウド基盤まで、対象は幅広い。

内容は「このレジストリ設定はこうすべき」「このポリシーは有効化すべき」といった具体的なチェック項目の集合体で、セキュリティ監査やアセスメントの現場で広く参照されている。

---

## 補足：関連用語の整理（CVSS・CVE・CWEとの違い）

CIS Benchmarksと混同されやすい用語をあらためて整理しておく。位置づけが異なるため、まとめて覚えておくと理解しやすい。

| 用語 | 位置づけ | 具体的な役割 |
|---|---|---|
| CVE (Common Vulnerabilities and Exposures) | 個々の脆弱性の識別番号 | 「CVE-2024-XXXXX」のように脆弱性そのものを一意に特定する |
| CVSS (Common Vulnerability Scoring System) | 脆弱性の深刻度スコア | CVEに対して0.0〜10.0のスコアを付け、緊急度を判断する |
| CWE (Common Weakness Enumeration) | 脆弱性の種類・パターンの分類 | SQLインジェクションやバッファオーバーフローなど、脆弱性の「型」を分類する |
| CIS Benchmarks | セキュリティ設定の推奨基準 | 個別の脆弱性ではなく、OSやミドルウェアの**設定そのもの**が安全かどうかを判断する基準 |

> **ポイント**: CVE・CVSS・CWEは「発見された脆弱性」を扱う枠組みであるのに対し、CIS Benchmarksは「そもそも設定として何を推奨するか」を扱う枠組みである。両者は補完関係にあり、片方だけでは十分なセキュリティ評価にならない。

## CIS Benchmarksの構成

CIS Benchmarksの各項目は、主に以下の情報で構成されている。

- **番号**（例: `1.1.1`、`2.3.10.1`）による階層構造
- **タイトル**（例: "Ensure 'Minimum password length' is set to '14' or more"）
- **Profile Applicability**（Level 1 / Level 2）
- **Description / Rationale**（設定の説明となぜ必要かの根拠）
- **Audit**（現在の設定を確認する手順）
- **Remediation**（設定を修正する手順）

Level 1とLevel 2の違いは以下のとおりだ。

| プロファイル | 想定環境 | 特徴 |
|---|---|---|
| Level 1 | 一般的な環境 | 機能性への影響が少ない、まず適用すべき基本設定 |
| Level 2 | セキュリティ重視の環境 | より厳格だが、機能制限が発生しうる |

また、同じ製品（例: Windows Server 2022）でも、用途に応じて複数バージョンのベンチマークが用意されている。

- **通常のCIS Benchmark**: Level 1/Level 2の一般的な基準
- **Stand-alone Benchmark**: ドメイン参加していない単体サーバー向け
- **STIG Benchmark**: 米国防総省傘下のDISAが定める**STIG（Security Technical Implementation Guide）**の基準に整合させたバージョン。政府機関や防衛関連の顧客からSTIG準拠を求められる場合に使用する

> **注意**: 顧客からの要求が特にない限り、通常は一般向けのCIS Benchmark（Level 1/2）を使うケースが多い。STIG版は政府・防衛関連など、要件が明示されている場合に選択すればよい。

## 入手方法の違い（PDF版とExcel版）

CIS Benchmarksの入手方法には、無料と有償で明確な違いがある。監査業務でExcelにチェック結果を記入して納品する場合、この違いを理解しておく必要がある。

| | 無料（一般公開） | CIS SecureSuite Membership（有償） |
|---|---|---|
| 入手先 | cisecurity.org（メールアドレス登録のみ） | CIS WorkBench（有償会員ログイン） |
| 形式 | PDFのみ | PDF + Excel / Word / XML / OVAL |
| カスタマイズ | 不可 | 組織向けにベンチマーク項目をカスタマイズ可能 |
| その他特典 | なし | CIS-CAT Pro（自動チェックツール）、CIS Build Kits（自動適用ツール）など |

**CIS Benchmarks** と **CIS WorkBench** は名前が似ているが、役割が異なる。

- **CIS Benchmarks**: 成果物（コンテンツ）そのもの。推奨設定集のPDF文書群を指す
- **CIS WorkBench**: プラットフォーム（場）。ベンチマークを作成・議論するコミュニティの拠点であり、ログインすることで各種形式のダウンロードやカスタマイズが可能になる

WorkBenchへのアカウント登録自体は無料だが、**Excel/Word/XML/OVAL形式でのエクスポート機能はSecureSuite Membership（有償）の会員向け機能**である点に注意したい。

## 活用方法 / ユースケース

CIS Benchmarksは、セキュリティ監査やアセスメントの現場で以下のように使われることが多い。

- サーバー構築時のハードニング（要塞化）チェックリストとして使用する
- 監査業務でExcel化した項目に「適用済 / 対象外 / 未対応」などの判定を記入し、顧客への納品物として使用する
- 自動チェックツール（CIS-CAT Proなど）と組み合わせて、定期的なコンプライアンスチェックに使用する

## メリット・デメリット

CIS Benchmarksを利用する上でのメリット・デメリットは以下のとおりだ。

**メリット**

- 業界標準として広く認知されており、顧客への説明がしやすい
- Level 1/Level 2で環境に応じた強度を選べる
- 対象製品が幅広く、OS以外（クラウド、ブラウザなど）にも対応している

**デメリット**

- 項目の記述が抽象的で、実際にOS上のどこ（GPOのパス、レジストリキーなど）を指しているか分かりにくい場合がある
- Excel形式などの実務向けフォーマットは有償メンバーシップが前提になる
- 項目数が多く（製品によっては数百項目）、全項目のチェックには相応の工数がかかる

---

## この構成を選んだ理由（自身の観点）

監査業務でCIS Benchmarksを使う場合、PDFの英語記述だけでは対象の設定箇所が伝わりにくいという課題に直面することが多い。そのため、原文の英語列を残しつつ、日本語訳や設定箇所の補足（GPOパス、レジストリキーなど）を追加したExcelを作成する運用が有効だと考えている。抽象的な記述をそのまま納品するのではなく、補足を加えることで顧客への伝わりやすさが大きく変わる。

---

## まとめ

CIS Benchmarksは、OSやミドルウェアの**セキュリティ設定そのもの**を評価するための業界標準の基準であり、個々の脆弱性を扱うCVE・CVSS・CWEとは役割が異なる。無料で入手できるのはPDF版のみで、Excel等の実務向けフォーマットはCIS WorkBench経由の有償メンバーシップが前提になる点を押さえておきたい。

- CIS Benchmarks: 設定の推奨基準（コンテンツ）
- CIS WorkBench: それを配信・カスタマイズするプラットフォーム
- CVE/CVSS/CWE: 個々の脆弱性を扱う別枠組み

これらの位置づけを整理しておくことで、監査業務での基準選定や顧客への説明がスムーズになるはずだ。
